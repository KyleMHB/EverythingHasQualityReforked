## Rule model and settings lifecycle

Provide Include, Exclude and Inherit for branches and individual items. Each definition has a quality-group default. Resolve an explicit item exception first, then the deepest matching explicit branch rule, then the group default. Use category-tree depth from a stable root; descendant rules outrank ancestors and equal-specificity conflicting rules resolve to Exclude. Explain the winning rule. The resolver is deterministic regardless of dictionary iteration order.

Keep assignment and effects as separate policies sharing the same catalog and precedence algorithm. An assignment-excluded native-quality weapon can still be explicitly included in an optional effect. An item without actual quality cannot receive an effect; show that reason. Unsupported objects such as pawns, corpses or non-component-capable things cannot be forced into assignment by an Include rule. Preserve derived/custom quality components and third-party component properties; do not create duplicates by assuming exact class equality proves absence.

Use a draft copy in the options, a saved next-session configuration and an immutable active snapshot. Tab navigation does not save. Save validates and persists; Discard restores the draft. Closing with edits offers Save, Discard or Continue editing. Every saved behavior change activates after restarting RimWorld, including saves made from the main menu. Show a pending summary, and clearly explain when removal of mod-added quality support can discard those quality values on a later save.

At startup, build the catalog after definitions/patches are available, capture native support and add only the components this mod owns. Respect integration ordering and the pack's startup caches; do not assume metadata or a cached startup proves correct synchronization. Any needed legacy save migration must operate narrowly during loading and preserve other component instances/state. No whole-map ticking conversion is allowed.

## Options UI

Use three pages: Quality Rules, Production, and Compatibility. Quality Rules contains the group/category browser, item results, selected-item details and assignment/effect controls; Production contains material/table/skill/inspiration calculations. Compatibility reports patch and adapter availability with useful reasons.

- Browse broad groups and the real category hierarchy, including mod-added branches. Browsing, expanding and filtering never change a rule.
- Display translated item/category names, source mod, effective result and governing rule. Keep internal names available in tooltips/advanced search.
- Search labels, internal identifiers, categories and source mods. Filters include group/category, source mod, participation and explicit overrides.
- Bulk Include matching items, Exclude matching items and Clear matching overrides operate on the entire filtered result, not just visible rows. Preview the count and preserve unrelated rules.
- Distinguish inherited state, mixed descendant results, unsupported items and protected native quality. Show counts and pending changes.
- Resets have explicit scope: selected group/branch, item overrides or everything. Confirm broad resets without making routine single-item changes cumbersome.
- Use row-aligned named quality selectors, stable numeric edit buffers, responsive coordinates relative to the supplied rectangle, scrolling and virtualized lists. Restore drawing state and localize new strings.
- Use one small effects catalog with named effect switches and advanced seven-tier factors; do not introduce a scripting engine or separate UI implementation per family.

Acceptance examples: enable resources, exclude textiles, include cloth; exclude silver without enabling an individual mode; find a modded item by its in-game name; bulk-edit only search matches; and reopen/restart without losing exceptions or confusing saved and active behavior.

## State, save compatibility and migration

- Freshly generated items finish initialization at intended starting condition. Construction preserves the frame's damage ratio. Genuine subsequent quality changes preserve condition percentage: 50/100 becomes 60/120. Settings changes preserve absolute HP and clamp excess; no automatic healing. Clear affected stat/repair caches before comparing maxima.
- Battery capacity changes preserve absolute energy and clamp excess; never create charge by preserving percentage. Reducing storage capacity never deletes contents: stop extra acceptance and use the supported storage/hauling overflow behavior.
- Determine drug strength/duration from the consumed dose while retaining the drug's native redosing/stacking policy. Existing untracked effects start at Normal-equivalent behavior. Saved settings changes do not retroactively strengthen active doses; store only the minimal per-dose state needed. Unsupported paths remain native, not guessed replacements.
- If bionics are included, initialize existing installed parts at Normal and transfer quality through exact surgery/removed-item/body-part records. Do not reroll installed parts.
- Add a settings schema version and back up legacy settings before migration. Preserve saved scalars/ranges and misspelled weapon keys. Import both true and false entries from enabled legacy individual modes as explicit exceptions, including entries equal to today's default. Retain unavailable-mod entries inactive. Keep disabled legacy selections inactive and recoverable. New definitions inherit. Null collections and invalid ranges recover safely with a concise diagnostic. Migration is idempotent.
- Do not promise lossless uninstall. Prefer native persistence and derived effects. Where selected persistent state requires cleanup, provide a bounded disable/normalize path or document exact supported removal limits; include inventories/containers/world-held things. Never silently resave the user's colony or change shared definitions as a shortcut.
